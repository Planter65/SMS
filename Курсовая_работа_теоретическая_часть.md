# 1. ТЕОРЕТИЧЕСКАЯ ЧАСТЬ

## 1.1 АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ

### 1.1.1 Общая характеристика предметной области

**Система СМС информирования "РИА СПЕКТР"** представляет собой комплексное веб-приложение, предназначенное для автоматизации процесса массовой рассылки SMS-сообщений среди сотрудников, клиентов и партнеров организации. 

**Актуальность разработки** обусловлена необходимостью современных организаций в эффективных инструментах коммуникации. В условиях цифровизации бизнес-процессов SMS-сообщения остаются одним из наиболее надежных и быстрых способов доставки критически важной информации, особенно в ситуациях, когда интернет-соединение может быть недоступно или ограничено.

**Проблематика предметной области** заключается в том, что традиционные методы отправки SMS (через мобильные телефоны или простые приложения) не обеспечивают:
- Централизованного управления базой контактов
- Массовой рассылки с персонализацией
- Отслеживания статуса доставки сообщений
- Анализа эффективности коммуникационных кампаний
- Интеграции с корпоративными системами

Система решает эти проблемы, предоставляя единую платформу для управления всей коммуникационной активностью организации. Она обеспечивает централизованное управление контактами, шаблонами сообщений и отслеживание доставки уведомлений, что значительно повышает эффективность корпоративных коммуникаций.

### 1.1.2 Назначение и область применения

**Целевое назначение системы** заключается в создании единой платформы для управления корпоративными коммуникациями через SMS-канал. Система предназначена для организаций различного масштаба - от малых предприятий до крупных корпораций, которым необходимо поддерживать эффективную связь с различными группами заинтересованных сторон.

**Области применения системы:**

#### Корпоративные уведомления
Система обеспечивает оперативное информирование сотрудников о:
- **Важных событиях** — изменения в политике компании, новые проекты, достижения
- **Совещаниях и встречах** — напоминания о предстоящих мероприятиях с деталями
- **Изменениях в расписании** — корректировки рабочего времени, отпусков, командировок
- **Системных уведомлениях** — технические работы, обновления IT-инфраструктуры

**Преимущества:** Высокая скорость доставки (до 3 секунд), гарантированное получение сообщения независимо от наличия интернета у получателя.

#### Клиентская коммуникация
Система позволяет поддерживать связь с клиентской базой:
- **Уведомления об услугах** — информация о новых предложениях, изменениях в тарифах
- **Акции и специальные предложения** — персонализированные маркетинговые сообщения
- **Изменения в регламенте работы** — график работы, контактная информация
- **Напоминания о платежах** — уведомления о задолженности, предстоящих списаниях

**Преимущества:** Прямой канал связи с клиентом, высокая открываемость SMS (до 98%), возможность персонализации сообщений.

#### Внутрикорпоративная связь
Система обеспечивает эффективную коммуникацию между сотрудниками:
- **Служебные сообщения** — поручения, запросы информации, координация работы
- **Межотделенческое взаимодействие** — уведомления о готовности документов, результатах работы
- **Экстренные оповещения** — критические ситуации, требующие немедленного реагирования

**Преимущества:** Быстрая координация действий, снижение времени на поиск и передачу информации.

#### Маркетинговые кампании
Система поддерживает проведение целевых маркетинговых мероприятий:
- **Информирование о новых продуктах** — анонсы, характеристики, условия приобретения
- **Персональные предложения** — индивидуальные скидки, специальные условия
- **Событийный маркетинг** — приглашения на мероприятия, вебинары, презентации
- **Программы лояльности** — уведомления о накопленных бонусах, специальных акциях

**Преимущества:** Высокая конверсия (до 15%), возможность сегментации аудитории, измерение эффективности кампаний.

#### Оперативные оповещения
Система обеспечивает экстренное информирование:
- **Критические ситуации** — аварии, сбои в работе систем, угрозы безопасности
- **Изменения в режиме работы** — временные закрытия, переносы мероприятий
- **Технические уведомления** — плановые работы, обновления, профилактика
- **Правовые изменения** — новые требования законодательства, изменения в договорах

**Преимущества:** Мгновенная доставка критически важной информации, возможность массового оповещения за короткое время.

**Экономическая эффективность** использования системы проявляется в:
- Сокращении времени на подготовку и отправку уведомлений (с часов до минут)
- Снижении затрат на альтернативные каналы связи (почта, телефонные звонки)
- Повышении оперативности реагирования на события
- Улучшении качества обслуживания клиентов
- Снижении количества пропущенных важных событий

### 1.1.3 Основные действующие лица (актеры)

**Модель ролей и прав доступа** в системе построена на принципе разделения ответственности и минимизации привилегий. Каждый пользователь получает доступ только к тем функциям, которые необходимы для выполнения его профессиональных обязанностей.

#### Администратор системы (Admin)

**Роль и ответственность:**
Администратор системы является главным оператором с неограниченными правами доступа. Эта роль предназначена для IT-специалистов, системных администраторов или руководителей, ответственных за функционирование корпоративных коммуникаций.

**Детализированные задачи администратора:**

**Управление базой данных получателей:**
- **Добавление новых получателей** — ввод контактной информации, проверка корректности номеров телефонов
- **Редактирование существующих записей** — обновление персональных данных, изменение принадлежности к группам
- **Удаление получателей** — с проверкой связанных записей и возможностью восстановления
- **Массовые операции** — импорт/экспорт контактов из внешних систем (Excel, CRM, базы данных)

**Управление группами получателей:**
- **Создание групп** — определение категорий для сегментации аудитории (сотрудники, клиенты, поставщики)
- **Настройка групповых политик** — установка правил доступа к группам, ограничений на отправку
- **Иерархическая организация** — создание подгрупп и связей между группами
- **Автоматическая классификация** — настройка правил автоматического распределения получателей по группам

**Формирование и отправка массовых рассылок:**
- **Создание шаблонов сообщений** — разработка стандартных текстов для различных типов уведомлений
- **Персонализация сообщений** — использование переменных для индивидуальной настройки текста
- **Планирование рассылок** — настройка отложенной отправки, повторяющихся уведомлений
- **A/B тестирование** — создание вариантов сообщений для оптимизации эффективности

**Аналитика и отчетность:**
- **Статистика доставки** — анализ успешности отправки сообщений, выявление проблемных номеров
- **Эффективность кампаний** — измерение отклика на различные типы сообщений
- **Финансовая отчетность** — расчет стоимости рассылок, анализ ROI маркетинговых кампаний
- **Пользовательская активность** — мониторинг действий пользователей системы

**Управление пользователями:**
- **Создание учетных записей** — регистрация новых пользователей с назначением ролей
- **Управление правами доступа** — настройка разрешений для различных функций системы
- **Блокировка и разблокировка** — временное ограничение доступа при нарушении политик безопасности
- **Аудит безопасности** — мониторинг попыток несанкционированного доступа

**Системное администрирование:**
- **Резервное копирование** — создание и восстановление резервных копий базы данных
- **Мониторинг производительности** — отслеживание нагрузки на систему, оптимизация запросов
- **Обновление системы** — установка обновлений, миграция данных
- **Интеграция с внешними системами** — настройка API для подключения к CRM, ERP и другим системам

**Права доступа администратора:**
- **Полный доступ ко всем функциям** — отсутствие ограничений на использование любых возможностей системы
- **Просмотр системных логов** — доступ к детальной информации о всех операциях в системе
- **Управление конфигурацией** — изменение настроек системы, параметров безопасности
- **Экспорт данных** — возможность выгрузки всей информации из системы в различных форматах

#### Пользователь системы (User)

**Роль и ограничения:**
Пользователь системы — это обычный сотрудник организации с ограниченным набором функций, предназначенным для выполнения повседневных задач по отправке сообщений. Эта роль обеспечивает баланс между функциональностью и безопасностью.

**Детализированные задачи пользователя:**

**Управление личными сообщениями:**
- **Просмотр входящих сообщений** — получение и чтение сообщений от других пользователей системы
- **Отправка персональных сообщений** — создание и отправка SMS другим пользователям системы
- **Управление статусом прочтения** — отметка сообщений как прочитанных, архивирование
- **Поиск в истории сообщений** — быстрый поиск по отправителю, дате, содержанию

**Работа с получателями:**
- **Просмотр доступных получателей** — просмотр списка контактов, к которым пользователь имеет доступ
- **Фильтрация по группам** — выбор получателей из определенных категорий
- **Поиск контактов** — быстрый поиск получателей по имени или номеру телефона
- **Синхронизация данных** — обновление информации о получателях из корпоративных систем

**Отправка сообщений:**
- **Создание текста сообщения** — написание SMS с учетом ограничений по длине (160 символов)
- **Выбор получателей** — индивидуальный выбор или массовый выбор по группам
- **Предварительный просмотр** — проверка текста и списка получателей перед отправкой
- **Отслеживание статуса** — просмотр информации о доставке отправленных сообщений

**Просмотр статистики:**
- **Личная статистика** — количество отправленных сообщений, успешность доставки
- **История активности** — хронология всех действий пользователя в системе
- **Анализ эффективности** — статистика по различным типам отправленных сообщений

**Ограничения пользователя:**
- **Отправка только пользователям системы** — невозможность отправки SMS внешним получателям
- **Ограниченный доступ к управлению** — отсутствие возможности изменения системных настроек
- **Просмотр только собственной статистики** — невозможность доступа к аналитике других пользователей
- **Ограниченные права на получателей** — только просмотр, без возможности добавления или изменения

**Процесс авторизации пользователя:**
1. **Ввод учетных данных** — логин и пароль через защищенную форму
2. **Проверка блокировки** — система проверяет статус аккаунта и количество неудачных попыток входа
3. **Аутентификация** — проверка существования пользователя и корректности пароля
4. **Определение роли** — система определяет уровень доступа на основе роли пользователя
5. **Создание сессии** — инициализация пользовательской сессии с установкой соответствующих прав
6. **Перенаправление** — переход на соответствующую панель управления (admin.php или user.php)

**Модель безопасности для пользователей:**
- **Минимальные привилегии** — пользователь получает доступ только к необходимым функциям
- **Аудит действий** — все действия пользователя логируются в системном журнале
- **Сессионное управление** — автоматическое завершение сессии при неактивности
- **Защита от злоупотреблений** — ограничения на количество отправляемых сообщений

### 1.1.4 Основные сущности предметной области

**Концептуальная модель данных** системы построена на основе реляционной модели с четким разделением сущностей и установлением связей между ними. Каждая сущность представляет собой логически завершенный объект предметной области с определенным набором атрибутов и бизнес-правил.

#### Пользователь (User)

**Концептуальное описание:**
Пользователь представляет собой учетную запись сотрудника организации, имеющего авторизованный доступ к системе СМС информирования. Эта сущность является центральной в системе безопасности и определяет права доступа к различным функциям приложения.

**Детализированные атрибуты:**

**Идентификационные данные:**
- `UserID` (INT, PRIMARY KEY, AUTO_INCREMENT) — уникальный числовой идентификатор пользователя, используемый для внутренних связей в базе данных
- `Username` (VARCHAR(50), UNIQUE, NOT NULL) — уникальное имя пользователя для входа в систему, должно соответствовать корпоративным стандартам именования

**Данные безопасности:**
- `PasswordHash` (VARCHAR(255), NOT NULL) — хешированный пароль пользователя, созданный с использованием алгоритма `password_hash()` с параметром `PASSWORD_DEFAULT`
- `PasswordCreatedAt` (DATETIME, NOT NULL) — дата и время создания текущего пароля, используется для контроля срока действия пароля (6 месяцев)
- `FailedLoginCount` (INT, DEFAULT 0) — счетчик неудачных попыток входа, используется для блокировки аккаунта при превышении лимита (5 попыток)
- `LastFailedLoginAt` (DATETIME, NULL) — время последней неудачной попытки входа, используется для анализа попыток взлома

**Ролевая модель:**
- `Role` (ENUM('admin', 'user'), NOT NULL) — роль пользователя в системе, определяющая уровень доступа:
  - `admin` — полный доступ ко всем функциям системы
  - `user` — ограниченный доступ только к функциям отправки сообщений

**Статус и аудит:**
- `Status` (ENUM('active', 'blocked'), DEFAULT 'active') — текущий статус аккаунта:
  - `active` — аккаунт активен и может использоваться
  - `blocked` — аккаунт заблокирован администратором или системой безопасности
- `CreatedAt` (DATETIME, NOT NULL) — дата и время создания учетной записи
- `UpdatedAt` (DATETIME, NOT NULL) — дата и время последнего обновления записи

**Бизнес-правила и ограничения:**

**Правила именования:**
- Логин должен быть уникальным в рамках системы
- Логин должен содержать от 3 до 50 символов
- Разрешены только латинские буквы, цифры и символы подчеркивания
- Логин не может начинаться с цифры

**Правила безопасности паролей:**
- Минимальная длина пароля — 8 символов
- Обязательное наличие букв (строчных и заглавных)
- Обязательное наличие цифр
- Обязательное наличие специальных символов (!@#$%^&*(),.?":{}|<>)
- Пароль не может совпадать с логином или его вариациями
- Автоматическая блокировка после 5 неудачных попыток входа
- Принудительная смена пароля каждые 6 месяцев

**Примеры валидных паролей:**
- `MyPass123!` — содержит буквы, цифры и специальный символ
- `Secure2024#` — соответствует всем требованиям безопасности
- `Admin@2025` — подходит для административных аккаунтов

**Примеры невалидных паролей:**
- `12345678` — только цифры, нет букв и специальных символов
- `password` — только буквы, нет цифр и специальных символов
- `Pass123` — недостаточная длина (менее 8 символов)

#### Получатель (Recipient)

**Концептуальное описание:**
Получатель представляет собой физическое лицо или контакт, которому может быть отправлено SMS-сообщение. Эта сущность содержит контактную информацию и метаданные, необходимые для организации рассылок и анализа эффективности коммуникаций.

**Детализированные атрибуты:**

**Идентификационные данные:**
- `RecipientID` (INT, PRIMARY KEY, AUTO_INCREMENT) — уникальный числовой идентификатор получателя
- `FullName` (VARCHAR(100), NOT NULL) — полное имя получателя в формате "Фамилия Имя Отчество"

**Контактная информация:**
- `PhoneNumber` (VARCHAR(20), NOT NULL) — номер мобильного телефона в международном формате (+7XXXXXXXXXX)
- `GroupID` (INT, FOREIGN KEY) — ссылка на группу получателей для категоризации

**Метаданные:**
- `CreatedAt` (DATETIME, NOT NULL) — дата добавления получателя в систему
- `UpdatedAt` (DATETIME, NOT NULL) — дата последнего обновления информации
- `IsActive` (BOOLEAN, DEFAULT TRUE) — флаг активности получателя (возможность временного отключения)

**Бизнес-правила и валидация:**

**Правила валидации номера телефона:**
- Номер должен соответствовать российскому формату (+7XXXXXXXXXX)
- Длина номера должна составлять 12 символов (включая код страны)
- Номер должен начинаться с +7 (Россия)
- Второй символ должен быть 9 (мобильные номера)
- Остальные 9 символов должны быть цифрами

**Примеры валидных номеров:**
- `+79123456789` — корректный мобильный номер
- `+79001234567` — корректный мобильный номер
- `+79991234567` — корректный мобильный номер

#### Группа получателей (Group)

**Концептуальное описание:**
Группа получателей представляет собой логическую категоризацию контактов по различным признакам, таким как должность, отдел, статус клиента или тип взаимоотношений с организацией. Группировка позволяет эффективно организовывать массовые рассылки и анализировать эффективность коммуникаций по сегментам аудитории.

**Детализированные атрибуты:**

- `UpdatedAt` (DATETIME, NOT NULL) — дата последнего обновления

**Типовые группы в корпоративной среде:**

#### Журнал отправки (MessageLog)

**Концептуальное описание:**
Журнал отправки представляет собой запись о каждой попытке отправки SMS-сообщения конкретному получателю. Эта сущность обеспечивает полную трассируемость коммуникационных процессов и является основой для аналитики и отчетности.

**Детализированные атрибуты:**

**Идентификационные данные:**
- `LogID` (INT, PRIMARY KEY, AUTO_INCREMENT) — уникальный идентификатор записи в журнале
- `MessageID` (INT, FOREIGN KEY) — ссылка на отправленное сообщение
- `RecipientID` (INT, FOREIGN KEY) — ссылка на получателя сообщения

**Информация об отправке:**
- `Status` (ENUM('pending', 'sent', 'delivered', 'failed', 'expired'), NOT NULL) — статус доставки сообщения:
  - `pending` — сообщение в очереди на отправку
  - `sent` — сообщение отправлено оператору связи
  - `delivered` — сообщение доставлено получателю
  - `failed` — ошибка при отправке
  - `expired` — сообщение не доставлено в течение срока действия
- `SentDate` (DATETIME, NOT NULL) — дата и время отправки сообщения
- `DeliveredDate` (DATETIME, NULL) — дата и время подтверждения доставки

**Техническая информация:**
- `OperatorCode` (VARCHAR(10), NULL) — код оператора связи получателя
- `Cost` (DECIMAL(10,2), NULL) — стоимость отправки сообщения
- `ErrorCode` (VARCHAR(20), NULL) — код ошибки при неудачной отправке
- `ErrorMessage` (TEXT, NULL) — описание ошибки

**Метаданные:**
- `CreatedAt` (DATETIME, NOT NULL) — дата создания записи в журнале
- `UpdatedAt` (DATETIME, NOT NULL) — дата последнего обновления статуса

**Бизнес-правила:**

**Правила статусов:**
- Каждое сообщение должно иметь статус
- Статус может изменяться только в определенной последовательности
- Статус `delivered` может быть установлен только после статуса `sent`
- Статус `failed` является финальным и не может быть изменен

**Правила временных меток:**
- `SentDate` устанавливается при первой попытке отправки
- `DeliveredDate` устанавливается только при получении подтверждения доставки
- Временные метки должны быть в часовом поясе сервера

**Аналитические возможности:**
- Подсчет общего количества отправленных сообщений
- Анализ успешности доставки по группам получателей
- Расчет средней стоимости отправки
- Выявление проблемных номеров телефонов
- Анализ эффективности по времени отправки

### 1.1.5 Основные бизнес-процессы

#### Процесс отправки массовых SMS
**Этапы процесса:**
1. **Подготовка текста сообщения** — пользователь формирует текст сообщения (до 160 символов)
2. **Выбор получателей** — пользователь выбирает получателей из списка с возможностью фильтрации по группам
3. **Отправка сообщений** — система создает записи в журнале отправки и эмулирует отправку SMS

#### Процесс авторизации и аутентификации
**Этапы процесса:**
1. **Ввод учетных данных** — пользователь вводит логин и пароль
2. **Проверка блокировки** — проверка статуса аккаунта и количества неудачных попыток
3. **Аутентификация** — проверка существования пользователя и корректности пароля
4. **Авторизация** — определение роли пользователя и перенаправление на соответствующую панель

```php
// Пример функции аутентификации пользователя
function authenticateUser($username, $password) {
    $conn = connectToDatabase();
    $stmt = $conn->prepare("SELECT UserID, Username, PasswordHash, Role, Status FROM users WHERE Username = ?");
    $stmt->bind_param("s", $username);
    $stmt->execute();
    $result = $stmt->get_result();
    
    if ($row = $result->fetch_assoc()) {
        if (password_verify($password, $row['PasswordHash'])) {
            return ['success' => true, 'user' => $row];
        }
    }
    return ['success' => false, 'message' => 'Неверные учетные данные'];
}
```

```php
function connectToDatabase() {
    $conn = new mysqli(DB_HOST, DB_USERNAME, DB_PASSWORD, DB_NAME, DB_PORT);
    
    if ($conn->connect_error) {
        die("Ошибка подключения к базе данных: " . $conn->connect_error);
    }

}
```

**Подготовленные запросы для безопасности:**
```php
function addRecipient($data) {
    $conn = connectToDatabase();
    
    $stmt = $conn->prepare("INSERT INTO recipients (PhoneNumber, FullName, GroupID, CreatedAt, UpdatedAt) VALUES (?, ?, ?, NOW(), NOW())");
    $stmt->bind_param("ssi", $data['phone'], $data['name'], $data['group_id']);
    
    if ($stmt->execute()) {
        $conn->close();
        return ['success' => true, 'message' => 'Получатель успешно добавлен'];
    } else {
        $conn->close();
        return ['success' => false, 'message' => 'Ошибка при добавлении получателя'];
    }
}
```

**Транзакции для обеспечения целостности данных:**
```php
function sendSMS($messageId, $recipientIds) {
    $conn = connectToDatabase();
    $conn->begin_transaction();
    
    try {
        foreach ($recipientIds as $recipientId) {
            $stmt = $conn->prepare("INSERT INTO messagelogs (MessageID, RecipientID, Status, SentDate) VALUES (?, ?, 'sent', NOW())");
            $stmt->bind_param("ii", $messageId, $recipientId);
            $stmt->execute();
        }
        
        $conn->commit();
        return ['success' => true, 'message' => 'SMS успешно отправлены'];
    } catch (Exception $e) {
        $conn->rollback();
        return ['success' => false, 'message' => 'Ошибка при отправке SMS: ' . $e->getMessage()];
    } finally {
        $conn->close();
    }
}
```
