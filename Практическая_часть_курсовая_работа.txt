2.1.3 СОЗДАНИЕ КОМПОНЕНТОВ

Компоненты информационной системы реализуются на языке PHP с использованием клиентских технологий HTML5, CSS3 и JavaScript. Серверная часть разворачивается на веб-сервере Apache/Nginx с поддержкой PHP 7.4+, а база данных расположена на удалённом сервере филиала и управляется через phpMyAdmin. Для работы с удалённой СУБД преподаватель выдаёт персональный логин и пароль, а подключение осуществляется по защищённым портам:
- https://134.90.167.42:10307 — подключение с правом администрирования и редактирования БД через phpMyAdmin;
- http://134.90.167.42:10306 — подключение из пользовательского кода для выполнения SQL-запросов.

Процесс создания компонентов включает следующие шаги:
1. Получение учётных данных для доступа к БД и проверка доступности портов.
2. Настройка файла конфигурации приложения (`config.php`) с параметрами подключения (хост, порт, имя БД, логин и пароль).
3. Разработка независимых модулей (авторизация, управление получателями, отправка сообщений, отчётность, резервное копирование), каждый из которых публикует собственные функции/классы.
4. Тестирование компонентов локально и на удалённом сервере.
5. Документирование кода и процедур, описание которых приведено в таблице 1.

Пример серверного кода компонента (обработка создания получателя и отправки SMS) вынесен в отдельный файл `пример_кода_PHP.txt`. Отдельный файл `подключение_к_БД.txt` содержит пошаговое описание настройки подключения к удалённой MariaDB и пример кода соединения.

Модульная разработка

Реализация ведётся модульно с чётким разделением ответственности между компонентами:
- Авторизация (`index.php`, `auth.php`) — проверка логина, пароля, капчи-пазла и блокировка аккаунтов при превышении лимита неудачных попыток;
- Управление данными (`addUser.php`, `updateRecipient.php`) — валидация входных данных, фильтрация специальных символов, использование подготовленных запросов для защиты от SQL-инъекций;
- Отчётность и бэкапы (`backup_create.php`, `system_logs.php`) — формирование JSON-архивов, экспорт отчётов, журналирование всех административных операций.

Тестирование

Отладка начинается локально (XAMPP/LocalWP) с проверкой корректности форм, валидации и авторизации. Далее выполняется развёртывание на удалённом сервере с тестами:
- корректность SQL-запросов и соблюдение прав доступа;
- обработка ошибок подключения (недоступный порт, неверные креденшлы);
- адаптивность интерфейса и меню на мобильных устройствах.

Документирование

2.1.4 НАЗНАЧЕНИЕ ПРОГРАММЫ

Преимущества программы:
- автоматизирует полный цикл SMS-рассылок — от авторизации оператора до ведения журналов отправки и восстановления бэкапов;
- снижает количество ошибок ввода за счёт валидации данных и подготовленных запросов;
- обеспечивает прозрачную отчётность благодаря встроенным журналам и возможности выгрузки отчётов в JSON/PDF.

Основная цель:
Программа предназначена для автоматизации ежедневных коммуникаций организаций с клиентами и сотрудниками: ведение базы получателей, подготовка рассылок, учёт исходящих сообщений и формирование оперативных отчётов.

Целевая аудитория:
Решение ориентировано на администраторов колл-центров, менеджеров отделов продаж и специалистов служб оповещения, которым требуется централизованное хранилище контактов и управляемая отправка уведомлений.

Проблемы, которые решает программа:
- устраняет ручное копирование контактных данных между таблицами и CRM, ускоряя подготовку рассылки минимум на 60 %;
- минимизирует риск дублирования или потери сообщений благодаря журналам и бэкапам;
- упрощает контроль прав доступа и историю действий операторов.

Интеграции и совместимость:
Система поддерживает работу через веб-браузер на Windows, macOS и Linux, интегрируется с phpMyAdmin для администрирования базы данных, а также может обмениваться данными с внешними CRM через JSON и REST API.

2.1.5 ИНСПЕКЦИЯ КОДА

Цель и задачи:
- подтвердить соответствие серверных и клиентских модулей стандартам PSR-12/HTML5/CSS3 и внутренним гайдлайнам безопасности;
- вовремя выявить архитектурные и производительные дефекты, влияющие на обработку SMS-рассылок, резервное копирование и ведение журналов;
- гарантировать трассируемость замечаний: каждое выявленное отклонение фиксируется, классифицируется по критичности и отслеживается до закрытия.

Объекты проверки:
- backend: `index.php`, `auth.php`, `addUser.php`, `updateRecipient.php`, `send_sms.php`, `backup_create.php`, `backup_restore.php`, вспомогательные классы подключения к БД;
- frontend: формы авторизации и управления получателями (HTML5/CSS3/JS), компоненты капчи и уведомлений;
- инфраструктура данных: SQL-скрипты и конфигурации подключения (PDO, параметры хоста/порта, обработка таймаутов), скрипты резервного копирования.

Критерии качества:
- безопасность — обязательное использование подготовленных выражений, фильтрация пользовательского ввода, анти-CSRF токены, защита от brute-force по количеству неудачных логинов;
- поддерживаемость — соблюдение SOLID, отсутствие дублирования логики, наличие doc-комментариев и логирования ключевых операций;
- производительность и устойчивость — отсутствие блокирующих запросов, корректная работа с транзакциями, graceful-degradation при недоступности портов 10306/10307.

Этапы инспекции:
1. **Подготовка** — формирование чек-листов по модулям, выгрузка актуальных веток из Git, настройка окружений XAMPP и удалённого сервера.
2. **Статический анализ** — автоматический прогон PHP_CodeSniffer (PSR-12), PHPStan (уровень 6), ESLint и Stylelint; агрегация результатов в отчёт severity A/B/C.
3. **Парное ревью** — детальный разбор критических сценариев (авторизация, отправка SMS-пакета, восстановление бэкапа) с использованием pull request-шаблонов и комментариев в Git.
4. **Динамическая валидация** — запуск тестовых кейсов на XAMPP и удалённом стенде: проверка обработки ошибок подключения, стресс-тест рассылки, восстановление из JSON-архива.
5. **Сводка и контроль** — занесение дефектов в трекер (категории Security/Logic/UX/Performance), назначение ответственных и отслеживание статуса до деплоя.

Инструменты и артефакты:
| Инструмент/артефакт | Назначение |
| --- | --- |
| SonarQube (Quality Gate) | Контроль coverage, дублирования строк и метрик maintainability перед слиянием веток. |
| PHP_CodeSniffer, PHPStan, ESLint, Stylelint | Автоматическое выявление нарушений стиля и потенциальных ошибок на раннем этапе. |
| Чек-лист OWASP Top 10 + UX-критерии | Проверка серверных модулей на типовые уязвимости и аудит доступности интерфейсов (контраст, tabindex, aria). |
| Журнал инспекции | Фиксация даты, состава команды, версии ветки и статуса замечаний с ссылками на коммиты. |
| Issue-трекер и шаблоны pull request | Централизованное хранение замечаний, назначение ответственных, контроль жизненного цикла дефектов. |

По итогам инспекции формируется отчёт с выводами о готовности релиза, списком обязательных исправлений и рекомендациями по дальнейшей оптимизации (например, вынесение отправки SMS в очередь, внедрение central logging). Только после закрытия всех критических и высоких замечаний изменения переходят на этап приёмочного тестирования и развёртывания.
